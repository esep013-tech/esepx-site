# 21.11.2026 — «Счета от поставщиков»

Миграций базы нет: робот ничего не хранит. Файл читается в браузере, после работы экран очищается.

- Браузер: `cabinet/inv.js` — чтение PDF из программы (pdf.js), Excel (SheetJS), Word (mammoth). Сканы и фото — отказ.
  Стандартный счёт 1С разбирается без ИИ: номер и дата, поставщик, БИН, ИИК, БИК, покупатель, договор, КНП, НДС, таблица. Сумма строк должна сходиться с «Итого».
  Иначе текст уходит в `inv-1c` → `read`. Перед этим `mask` заменяет БИН, ИИК, БИК, телефоны и почту метками, после ответа `unmask` возвращает их.
- Функция `inv-1c` (verify_jwt false, доступ внутри: `am_i_admin`, запись — `bank_can_write`). Действия:
  - `read` — ИИ (OPENAI_API_KEY);
  - `match` — только GET; поставщик строго по БИН, договоры, дубль счёта, 5 похожих номенклатур, заглушка «Внести», справочники для анкеты, люди для доверенности, счета фирмы. Служебный ключ сервера разрешён только для `match`;
  - `nom` — карточка номенклатуры по анкете;
  - `write` — счёт на оплату поставщика, платёжное поручение и доверенность.
- Документы 1С: `Document_СчетНаОплатуПоставщика` (Товары / Услуги, НомерВходящегоДокумента), `Document_ПлатежноеПоручениеИсходящее`, `Document_Доверенность`.
  - Платёжка: ОплатаПоставщику, ДокументОснование + строка СчетНаОплату_Key = счёт.
  - Доверенность: ДокументОснование_Key = счёт. Для строки с заглушкой `НаименованиеТовара` пишется строкой (`Edm.String`).
  - Автор и ответственный — «Робот». Документы не проводятся.
- Банковские счета: отбор по владельцу — `Owner eq cast(guid'…', 'Catalog_Организации')`.
- Несколько счетов: очередь в браузере (`invQ`), по каждому свой документ. «⬇ Файл для банк-клиента» — файл формата 1CClientBankExchange 2.00: UTF-8 без BOM, CRLF, по образцу выгрузки 1С Жанны от 20.11. Все платёжки сессии идут одним файлом, для каждого счёта фирмы — свой файл. Данные для файла (банки, их БИН, руководитель) отдаёт `write` в `print`.
- Назначение платежа — как делает 1С: «Оплата за <за что> согласно счету на оплату №N от <дата прописью> г. Сумма 23 374-00  теңге  без НДС». НДС в назначении и в строке платёжки ставится по статусу фирмы: если в прошлом счёте поставщика «УчитыватьНДС» = нет, пишется «без НДС».
- Разбор проверен на счетах Жанны: «Эгида Group» №5173 (xlsx, суммы вида 1,720.00, у колонки единицы нет заголовка) и «Мега Арсенал» №UT-1826 (pdf, «14 шт» в одной ячейке, заголовки по центру).
- Доверенность — «Кому»: ИП (`Catalog_Организации.ИндивидуальныйПредприниматель_Key`), работники (`Catalog_СотрудникиОрганизаций`, без уволенных), физлица из прошлых доверенностей, остальные физлица. Действие `person` создаёт физлицо по ФИО и ИИН (с проверкой контрольной цифры; если такой ИИН уже есть — берётся существующее).
- Удостоверения: регистр паспортных данных в OData базы «Мирас Строй» не опубликован (`InformationRegister_ПаспортныеДанныеФизЛиц` не найден). Данные вносятся в кабинете и проверяются в браузере и на сервере: номер удостоверения — 9 цифр, паспорта — N и 8 цифр; срок по умолчанию — дата выдачи + 10 лет; срок не раньше окончания доверенности. Пишутся в комментарий доверенности и в печать. Если регистр опубликуют, `idsOf` прочитает его сам.
- Повторы: по счёту ищутся платёжка (`ДокументОснование` = счёт) и доверенность (`ДокументОснование_Key` = счёт). Найденные показываются, новые не создаются; это проверяется и при записи.
- НДС: признак берётся из профиля фирмы (`companies.vat_payer`), если пусто — из прошлого счёта. Неплательщик: в счёте `УчитыватьНДС` = нет, ставка «без НДС», сумма НДС 0; в платёжке «без НДС»; у новой номенклатуры ставка «без НДС».
- Служебное действие `meta` (только по ключу сервера) ищет наборы в OData базы.
- Новый договор — всегда вид «Прочее» (жёсткое правило Жанны 21.11.2026), как и в выписках банка.
- Заглушки (решение Жанны 21.11.2026): «ТМЦ на сумму» (Услуга = нет) и «Услуга на сумму» (Услуга = да, строка в «Услуги» с настоящим текстом в «Содержание»). Если их нет — создаются при первой записи. В комментарии счёта: «Внести исправление, в СНО другая информация: <наименования>».
- Повторы ищутся двумя путями: по основанию (счёт в 1С) и по поставщику плюс номеру счёта в тексте («По документу» у доверенности, «Назначение платежа» у платёжки, с проверкой года). Найденный документ без основания робот после записи счёта привязывает одним PATCH: доверенности — `ДокументОснование_Key`; платёжке — `ДокументОснование`, а если она не проведена, ещё и `СчетНаОплату_Key` в строках.
- Комментарий доверенности — только «Создано роботом ESEP из счёта поставщика» (решение Жанны). Данные удостоверения идут только в печать.
