# 21.11.2026 — «Счета от поставщиков»

Миграций базы нет: робот ничего не хранит. Файл читается в браузере, после работы экран очищается.

- Браузер: `cabinet/inv.js` — чтение PDF из программы (pdf.js), Excel (SheetJS), Word (mammoth). Сканы и фото — отказ.
  Стандартный счёт 1С разбирается без ИИ: номер и дата, поставщик, БИН, ИИК, БИК, покупатель, договор, КНП, НДС, таблица. Сумма строк должна сходиться с «Итого».
  Иначе текст уходит в `inv-1c` → `read`. Перед этим `mask` заменяет БИН, ИИК, БИК, телефоны и почту метками, после ответа `unmask` возвращает их.
- Функция `inv-1c` (verify_jwt false, доступ внутри: `am_i_admin`, запись — `bank_can_write`). Действия:
  - `read` — ИИ (OPENAI_API_KEY);
  - `match` — только GET; поставщик строго по БИН, договоры, дубль счёта, 5 похожих номенклатур, заглушка «Внести», справочники для анкеты, люди для доверенности, счета фирмы. Служебный ключ сервера разрешён только для `match`;
  - `nom` — карточка номенклатуры по анкете;
  - `write` — счёт на оплату поставщика, платёжное поручение и доверенность.
- Документы 1С: `Document_СчетНаОплатуПоставщика` (Товары / Услуги, НомерВходящегоДокумента), `Document_ПлатежноеПоручениеИсходящее`, `Document_Доверенность`.
  - Платёжка: ОплатаПоставщику, ДокументОснование + строка СчетНаОплату_Key = счёт.
  - Доверенность: ДокументОснование_Key = счёт. Для строки с заглушкой `НаименованиеТовара` пишется строкой (`Edm.String`).
  - Автор и ответственный — «Робот». Документы не проводятся.
- Банковские счета: отбор по владельцу — `Owner eq cast(guid'…', 'Catalog_Организации')`.
