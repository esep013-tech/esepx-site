# 24.11.2026 — «Нужен доступ к 1С» (миграции onec_issues, onec_meta_cache)
- public.onec_issues: заявка администратору — company_id, feature (inv, inv_pp, inv_poa, akt, akt_make, bank, коды роботов), feature_name, missing (объекты OData), status open|done, waiting (кто ждёт), done_at/by. Одна открытая на фирму и автоматизацию. RLS: администратор — всё; пользователь видит заявки, где он ждёт.
- public.onec_meta: кэш списка EntitySet из $metadata базы (6 часов), только сервер. private.onec_meta создана по ошибке и не используется — можно удалить.
- Функция onec-need: check / robots / done (повторная проверка базы, затем events «Доступ к 1С открыт» фирме). Перечень нужного каждой автоматизации — константа NEEDS в функции.
- Кабинет: проверка перед счетами (и отдельно платёжкой и доверенностью), актами, выписками; при подключении роботов и при «Готов к работе»; вкладка «Управление → Доступ к 1С» (#admin/onec).
- Решение Жанны 24.11: у ИП в доверенности — адрес по местонахождению (вид «Фактический адрес физ. лица»), потом по прописке.

## 24.11 (позже) — миграция task_deadline_and_onec_tasks
- user_tasks.deadline — «крайний срок»; task_set_deadline(p_task, p_deadline, p_no_due); my_tasks отдаёт deadline и сортирует по coalesce(due, deadline); notify_digest_data — свои задачи по coalesce(due, deadline).
- tasks_repeat: опора повтора — срок или (если его нет) крайний срок; ежемесячные даты — на рабочий день; чек-лист копируется без отметок; «за <месяц>» в названии.
- onec_issues.task_ids — задачи администраторам по заявке (чек-лист: что открыть); «Отработано» закрывает их. Сообщение фирме — только если кто-то ждал.
- Триггер companies_onec_scan (private.onec_scan_kick): новая фирма или смена адреса 1С → onec-need scan.
- Пользователю подробности не показываются; при «Готов к работе» администратор сначала видит, что закрыто (confirm).
- ИП: адрес в доверенности — только «Фактический адрес физ. лица» (решение Жанны: по местонахождению, не по прописке).
